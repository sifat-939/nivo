# ছয়টি বাগের সংশোধন — ২৮ অক্টোবর ২০২৬

তিনটি `gpt-6-luna` সাব-এজেন্ট দিয়ে হিসাব, ব্যাকআপ এবং POS/UI-এর পরিবর্তন বাস্তবায়ন করা হয়েছে। মূল এজেন্ট কোড পর্যালোচনা, সম্মিলিত পরীক্ষা, প্যাকেজ করা অ্যাপ যাচাই এবং ইনস্টল করেছে। ব্যক্তিগত ডেটাবেসে পরীক্ষামূলক লেনদেন করা হয়নি।

## যা ঠিক হয়েছে

1. **পেমেন্ট বরাদ্দ:** প্রতি ইনভয়েসের সব reference row যোগ করে নিজস্ব বকেয়ার সঙ্গে তুলনা হয়। একই ইনভয়েসের duplicate row দিয়ে limit এড়ানো বা ঋণাত্মক বরাদ্দ দেওয়া যায় না। ভুল পেমেন্ট প্রত্যাখ্যানের পরে invoice/party balance এবং ledger অক্ষত থাকার পরীক্ষা আছে।
2. **রিটার্ন-পেমেন্ট বাতিল:** sales ও purchase return-এর refund cancel-এ allocation ফেরত যোগ হয়। Partial refund-এর submit/cancel-এ invoice/party outstanding এবং reversing ledger পরীক্ষা আছে; সাধারণ পেমেন্টের cancel-ও যাচাই করা হয়েছে।
3. **ব্যাকআপ:** timestamp ও suffix-সহ path exclusive creation দিয়ে reserve করা হয়। একই timestamp বা concurrent attempt-এও আগের recovery snapshot প্রতিস্থাপিত হয় না। Handle সবসময় বন্ধ হয়; অসম্পূর্ণ backup তৈরি ব্যর্থ হলে ওই reserved file সরানো হয়।
4. **POS closing validation:** ঋণাত্মক মানের error চাপা পড়ে না। Save/field mutation-এর আগেই validation হয়; child model-এও nonnegative validation আছে।
5. **Offline POS closing:** স্থানীয় close flow-তে `navigator.onLine` বাধা সরানো হয়েছে। Offline অবস্থায় বাস্তব closing shift save এবং nonzero cash JournalEntry posting পরীক্ষা হয়েছে। বাইরের ERP sync ব্যবস্থা পরিবর্তন হয়নি।
6. **টেমপ্লেটের duplicate popup:** mounted/activated-এর overlapping initialization একই pending promise ব্যবহার করে। কাজ শেষ হলে পরের activation আবার refresh করতে পারে। Template-এর type পরিবর্তনের স্বাভাবিক পথ রাখা হয়েছে।

## নিজে পরীক্ষা

```bash
scripts/test-nivo.sh

node uitest/nivo-template-regression.cjs
```

দ্বিতীয় কমান্ডের জন্য আগে Linux packaged build থাকতে হবে। এটি নতুন OS temporary directory-তে নিজস্ব test company/profile বানায়; ব্যক্তিগত ডেটাবেস নেয় না। `NIVO_APP_EXECUTABLE` দিয়ে নিজের তৈরি executable-এর পথ দেওয়া যায়।

সব unit/model regression অস্থায়ী বা in-memory ডেটায় চলে। `TS_NODE_TRANSPILE_ONLY` ব্যবহার করায় আলাদা static typecheck-ও তুলনা করা হয়েছে; তার সীমা নিচে লেখা আছে।

## সীমা

এগুলো অডিটে চিহ্নিত ছয়টি বাগের সমাধান; পুরো অ্যাপ বাগমুক্ত হওয়ার দাবি নয়। পরিবর্তন পুরোনো লেনদেন বা balance নিজে থেকে পুনর্লিখন করে না। আগে ভুল balance তৈরি হয়ে থাকলে তার জন্য পৃথক হিসাব মিলানোর কাজ প্রয়োজন। Windows/macOS-এর ইনস্টল ও সব POS hardware/receipt workflow এই Linux পরিবেশে পরীক্ষা হয়নি।

## পরীক্ষার ফল

- `scripts/test-nivo.sh`: Tape-এর **৯৭/৯৭ assertion** এবং asset packaging-এর **১টি Node regression test** পাস। এর মধ্যে পুরোনো invoice/payment পরীক্ষা ও নতুন প্রতিটি সমস্যার regression coverage আছে।
- Packaged Linux অ্যাপে Template Builder প্রথমবার খোলা এবং keep-alive reactivation-এ একটি warning; dismiss করলে দ্বিতীয়টি থাকে না। Renderer error পাওয়া যায়নি।
- Packaged অ্যাপে আগের test database, dashboard, logo এবং light/dark settings save/reload পাস।
- সংশোধিত তিনটি audit check script-ও পাস।
- পরিবর্তিত implementation-এর targeted ESLint, formatting এবং `git diff --check` পাস।
- `vue-tsc --noEmit --pretty false --types node`-এ baseline-এর মতো একই **২৫টি পূর্ববর্তী diagnostic** আছে; নতুন diagnostic নেই। সাধারণ default typecheck এখনও আগের অনুপস্থিত `webpack-env` types-এর কারণে থামে। সম্পূর্ণ static typecheck পরিষ্কার হয়েছে এমন দাবি করা হচ্ছে না।

সংশোধিত AppImage ইনস্টল করা হয়েছে। ইনস্টলার আগের ডেটা ও সেটিংসের ব্যাকআপ রেখেছে। ইনস্টলের আগে/পরে এবং অ্যাপ খোলার পর বিদ্যমান company ledger-এর checksum সমান; ইনস্টলের পরে configuration-ও অক্ষত ছিল। বাস্তব ইনস্টলে আগের নির্বাচিত কোম্পানি ও নতুন logo লোড হয়েছে, renderer error নেই।
